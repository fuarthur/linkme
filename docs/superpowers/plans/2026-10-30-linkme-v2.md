# LinkMe v2 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans for the tightly coupled app; use focused independent review/security-test work where useful.

**Goal:** Deliver a working native interest-discovery and chat app with a safe free backend.

**Architecture:** Retain Kotlin Android Views. A Firebase repository owns typed data operations; pure domain helpers own validation and ranking. Lifecycle-scoped UI listeners render explicit loading/error/empty states.

**Tech Stack:** Kotlin, Material 3 Views, AndroidX, Firebase Authentication / Firestore Spark.

**Spec:** docs/superpowers/specs/2026-10-30-linkme-v2-design.md

## Global Constraints

- Free Spark only; no billing or paid services.
- Preserve existing Users and Messages documents.
- PublicProfiles exposes no email or phone.
- Messages readable only by sender/receiver and cannot impersonate another sender.
- No GitHub push or store publishing.

## Review Focus

- A profile document write failing after authentication must never produce a successful onboarding state.
- A delayed send completion must preserve the newer draft; rapid taps must not duplicate sends.
- Missing auth or target ID must route safely instead of dereferencing null.
- Out-of-order discovery responses must not replace a newer selection.
- Private contacts, legacy messages and cross-user profile writes must be denied server-side.
